# Pre-built AITER JIT Kernels

Pre-compiled AITER attention kernels that eliminate ~280s of JIT
compilation on first inference request.

## How it works

1. **CI builds kernels** in an upstream ROCm/vLLM container on a CPU runner
   using `prebuild_aiter_kernels.py`, cross-compiling for each target
   architecture (gfx942, gfx950).
2. **Docker build** copies per-arch kernel directories into the image
   at `/workspace/aiter-jit-prebuilt/<arch>/`.
3. **At runtime**, `AIMRuntime.serve()` detects the GPU model from the
   selected profile, resolves its GFX architecture, and copies the
   matching pre-built `.so` files into AITER's system JIT directory
   before command generation runs. AITER finds both pre-built and system
   modules in one place.

The `.so` files are NOT stored in git — they are built fresh in CI.

## Read-only images

When AITER's package JIT directory is not writable (e.g. Apptainer/Slurm) or
`AITER_JIT_DIR` is set, the runtime instead symlinks the package modules and
the pre-built kernels (if any for the GPU arch) into `AITER_JIT_DIR`, and
exports it. With `AITER_JIT_DIR` set, AITER loads modules only from that
directory and writes runtime JIT builds there. Existing files are never
overwritten; broken symlinks are removed.

- Default `AITER_JIT_DIR`: `$TMPDIR/aiter-jit-<build>-<gfx_arch>-<uid>`,
  where `<build>` is a hash of `AIM_UPSTREAM_IMAGE_REF` and the installed
  AITER version. These fix the AITER build and toolchain, so runtime JIT
  builds are reused across restarts and by other AIM images with the same
  upstream image, AITER version, GPU arch and user. If the directory exists
  but is not private to the user (owned by someone else, a symlink, or open to
  other users), a fresh random directory is used instead.
- `AITER_ROOT_DIR` (AITER's codegen cache, default `~/.aiter`) defaults to
  `$AITER_JIT_DIR/root`, so caches are not shared across images via `$HOME`.
- This happens in `aim-runtime serve` only; scripts generated by
  `aim-runtime dry-run` (for inspection) don't include it.

AITER's own read-only fallback (`~/.aiter/jit`) is not used: it builds modules
it cannot import, and is shared across images.

## Directory structure (in image)

```
/workspace/aiter-jit-prebuilt/
├── gfx942/
│   ├── mha_varlen_fwd_fp16_*.so          (pre-built, ~1.2M each)
│   ├── mha_varlen_fwd_bf16_*.so          (pre-built, ~1.2M each)
│   └── module_fmha_v3_varlen_fwd.so      (pre-built, ~500K)
└── gfx950/
    └── (same structure, cross-compiled for gfx950)
```

## Kernel inventory (10 per arch)

| Kernel | Triggered by |
|--------|-------------|
| `mha_varlen_fwd_fp16_*_mask_nlse_*` | fp16 causal attention |
| `mha_varlen_fwd_fp16_*_mask_lse_*` | fp16 causal + LSE return |
| `mha_varlen_fwd_fp16_*_nmask_lse_*` | fp16 non-causal + LSE |
| `mha_varlen_fwd_fp16_*_nmask_nlse_*` | fp16 non-causal attention |
| `mha_varlen_fwd_bf16_*_mask_nlse_*` | bf16/fp8 causal attention |
| `mha_varlen_fwd_bf16_*_mask_lse_*` | bf16 causal + LSE return |
| `mha_varlen_fwd_bf16_*_nmask_lse_*` | bf16 non-causal + LSE |
| `mha_varlen_fwd_bf16_*_nmask_nlse_…skip_*` | bf16 non-causal attention |
| `mha_varlen_fwd_bf16_*_nmask_nlse_…nskip_*` | gemma-3 (min_seqlen_q=0) |
| `module_fmha_v3_varlen_fwd` | Flash Attention v3 ASM (bf16, head_dim=128) |

## Building manually

On any machine with GPU + ROCm + AITER:

```bash
python3 docker/prebuild_aiter_kernels.py --prebuild-device cuda --archs gfx942 gfx950
```

On a CPU-only machine running the ROCm/vLLM container:

```bash
python3 docker/prebuild_aiter_kernels.py --prebuild-device cpu --archs gfx942 gfx950
```

## Validation

Validated on `aim-base:0.11-rc21` (vLLM 0.16.0) with 13 model profiles.
100% JIT elimination, zero accuracy impact, up to 47% faster initial inference.
